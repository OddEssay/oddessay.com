# Restaurant cover

Resolve restaurant names by reading titles in `src/content/restaurants/*.md`; a draft's filename may not match its title. Reuse photos already supplied in the conversation or repository. For an explicitly requested new entry, reuse a matching draft or create one from supplied facts; ask only for required details that cannot be established. A new draft may receive its intended lowercase hyphenated filename; preserve established slugs.

1. Read the entry and current `src/lib/restaurant-schema.ts` before generating. Identify missing metadata and copied draft text early; preserve existing prose and report editorial leftovers. Restaurant files, cities and tags are discovered from Markdown: new lowercase hyphenated tags require no code registration. Resolve repository paths from the project root, not this skill directory.
2. Acquire and prepare the photo. Read [the image pipeline](../../../docs/restaurant-images.md) for iCloud retrieval, RAW/HEIC handling, provenance verification and oversized images. Archive the camera original byte-for-byte, then run `pnpm photo:prepare <decodable-source> src/assets/restaurants/<slug>/photo.png`. Reuse an identical prepared photo with its corresponding original; version changed inputs. Inspect image dimensions/file size before `view_image`: for oversized photos, inspect and supply a smaller proportional PNG reference while preserving the full-resolution photo. Separately inspect `src/assets/restaurants/garden-table.png` as the style-only reference. Read `docs/illustrations.md` for the established medium.
3. Use the built-in image-generation tool with both inspected references: the prepared photo (or its smaller reference) supplies subject/composition; the illustration supplies style only. Prefer `referenced_image_paths` for local inputs. If an input is only in the conversation, use the smallest `num_last_images_to_include` that includes both. Never provide both mechanisms.

   Prompt direction: “Transform reference 1 into hand-drawn black pencil and charcoal linework with a light monochrome wash on warm white paper, matching only the medium and texture of reference 2. Preserve reference 1’s subject, objects, composition, camera perspective, proportions, framing and aspect ratio. Keep object edges and landmarks aligned so this illustration can crossfade to the original photograph. Add no objects, text, logos or decorative borders.” Adapt subject details to the inspected photo; never borrow the style reference’s scene.
4. Inspect the generated image against the photo and style reference: object placement, perspective, proportions, crop alignment and paper texture. Correct an actionable input-format/size error before retrying; if generation remains unavailable or unusable, preserve the entry's image fields and report the failure. Do not substitute an invented original or silently switch to an API/CLI generator. Copy the selected output from the tool's returned location to `src/assets/restaurants/<slug>/cover-v1.png`, using its actual format and the next unused version for regenerations. Preserve previous assets.
5. Re-read the entry before editing so concurrent author edits survive. For an existing entry, patch only `image`, `imageAlt`, `originalImage`, and `originalImageAlt`; preserve other metadata, comments, prose and the final-newline state. Set `originalImage` to the full-resolution prepared photo, not the RAW archive or smaller generation reference. Use paths relative to the Markdown file, for example `../../assets/restaurants/<slug>/cover-v1.png`. Describe the depicted subject in each alt text, distinguishing illustration from photo. Record the final prompt, references and source provenance in `docs/illustrations.md` without signed URLs or access tokens.
6. Run `pnpm check`, then `pnpm build`, and inspect the entry diff. Verify both local image references decode and each has alt text. Fix failures introduced by the cover; if unresolved, restore only this task's image-field edits. For pre-existing metadata failures, report the exact field and distinguish a saved cover from a validated entry. Follow the pipeline's reload guidance if the dev server disagrees with a fresh check. Show the selected cover and asset paths; report validation accurately. Publishing is separate.

Image generation is an authoring step. CI and production builds only optimize committed local assets.
